# Ember localization contract v1

English and German everywhere a user reads Ember: the web app, the Android app (same bundle plus native strings), emails, notifications and the Discord bot. Server side: "Language v1.17" in api-v1.md.

## Languages and choice

- Codes `en` and `de`. A locale starting with `de` maps to `de`; everything else to `en`.
- Signed in: the app uses `Me.language`. Settings → Appearance gets a "Language" choice (English, Deutsch) that PATCHes it, like the theme.
- Signed out and no-account mode: the device language (`navigator.languages`), with the same Settings choice stored on the device only (`ember.language` in localStorage, try/catch). Signing in switches to the account's language.
- `<html lang>` always matches the shown language. Legal pages keep `lang="de"` for the German text.

## Tone (German)

- Informal "du", warm, short, plain, the same gentle voice as the English. No em dashes, en dashes or spaced hyphens. Habit, streak, low day: use "Habit", "Streak", "Tief" as the legal texts already do; "Gnadentage" for grace days.
- Wellness wording only, in both languages. German never-words: behandeln, Behandlung, heilen, Heilung, Therapie, therapeutisch, klinisch, diagnostizieren, Diagnose, vorbeugen, verhindern, lindern, reduzieren, bewiesen, nachgewiesen (a condition or symptom). The claims guard test covers both languages.

## Web

- `i18next` + `react-i18next`, resources bundled (no runtime fetch, so offline and signed-out work), `web/src/locales/en.json` and `de.json`, flat dotted keys grouped by screen (`today.door`, `moment.catch.title`, …). Plurals through i18next plural keys (Intl.PluralRules). Interpolation, no string concatenation.
- Dates, times and numbers shown to the user use `Intl` with the current language. Time-zone math (`local-date.ts`, `local/rules.ts`) keeps its fixed `en`/`en-US` formatters: those compute, they don't display.
- Tests run in English by default; a test helper renders in German where a test proves German output.
- A test fails when `de.json` and `en.json` have different keys or a German value is empty.

## Content files

- `web/src/content/practices.{en,de}.json` and `crisis-lines.{en,de}.json`: same ids, structure and numbers; only text differs. The validator checks every file and their parity (ids, steps, timings, numbers).
- `web/src/content/pitch.ts`: both languages. German pitch: hero "Ein kleines Lagerfeuer für große Momente.", meta and store "Ein ruhiger Begleiter für schwere Momente und sanfte Tage.", habits line "Und an den anderen Tagen: sanfte Habits." Door label: "Ich brauche einen Moment" (Android short label "Ein Moment").
- `web/public/release-notes.json`: `notes` becomes `{ "en": string[], "de": string[] }` (no shipped client reads the old shape). The What's new page, the Today card and the beta update prompt show the current language, falling back to `en`.

## Android

- `res/values-de/strings.xml` for every user-visible native string (widgets, shortcut, notification channels, the update and permission texts). Widgets follow the app's language through `EmberWidget.setLanguage({ language })` (called on start and on change). Phone reminder notifications are built by the web app and use its language. Launcher shortcut labels and widget names in the widget picker follow the device language (Android decides those).

## Server and bot

- .NET resource files (`.resx` read through `ResourceManager`) for text the server sends; shared text in Ember.Core, bot-only and email text in their projects; culture picked per message from `User.Language`, never from the server's culture.
- `/api/habit-templates` stays English; clients translate templates by `key`.
- Discord: replies, DMs, embeds, buttons and modals in the user's language. Slash command names stay English; their descriptions get German `DescriptionLocalizations`.
